# UMANOTE 改善プラン（結果レビュー）

最終更新: 2026-07-26  
親計画: [PLAN.md](./PLAN.md) / [DATA-AND-LOOP.md](./DATA-AND-LOOP.md)  
対象データ: `src/data/loop/evaluations/2026-07-25.json`・`2026-07-26.json`、`trends/latest.json`

運用ルールは DATA-AND-LOOP 通り **週次で変更は1つだけ**。本ドキュメントは「何を直す候補があるか」の棚卸し。

---

## 1. 結論（最重要）

1. **候補が多すぎる**（≈166 件/レース）— 製品目的「短時間で見極める」と矛盾
2. **スコアが高いほど複勝圏ヒットが悪い** — 注目穴が抑え候補より悪い（合成 factors が主因）
3. **実馬券的中は ≈0.4%** — 現行 Precision は関係馬の最良着順≤3 のため水増しされやすい
4. **3連複・3連単の払戻が未取得** — 仮想回収率が馬連・馬単に偏る

改善の効きやすい順: **指標の嘘を直す → 密度を落とす → 合成スコアを捨てる（D4）**

## 2. 結果サマリ

設定: `oddsThreshold=20` / `scoreMin=60` / 全券種 ON

| 日 | 候補 | 確定 | Precision（複勝圏） | Recall | 密度 | 仮想回収率 |
|----|------|------|---------------------|--------|------|------------|
| 2026-07-25 | 5944 | 5944 | 46.4% | 71.3% | ≈165 | 94.2% |
| 2026-07-26 | 6005 | 5124（待 881） | 40.0% | 76.8% | ≈167 | 44.3% |
| 合算（確定分） | — | 11068 | 43.4% | — | — | 71.1% |

補足:

| 指標 | 値 | 意味 |
|------|-----|------|
| 実払戻ヒット率（ticket） | ≈0.41% | `payoutYen > 0` の候補割合 |
| 候補/レース（中央値） | ≈170 | ボードが閲覧不能レベル |
| オッズ帯 100+ | 候補の約 8 割 | 超高配当ノイズが支配 |

注: factors が合成のあいだ、複勝圏 Precision は **製品挙動** の評価であり真の適性モデル評価ではない。

### 2.1 スコア帯別（逆転）

| スコア帯 | 複勝圏ヒット率（目安・2日） |
|----------|---------------------------|
| 60–64 | ≈49% |
| 65–69 | ≈42% |
| 70–79 | ≈32% |
| 80–89 | ≈20% |

→ `LABEL_SCORE_THRESHOLD=70`（注目穴）が **逆指標** になっている。

### 2.2 券種別（複勝圏ヒットの歪み）

3連単・3連複の placeHit が高いのは、関係馬のいずれかが3着以内なら hit になる定義の副作用。実払戻は両日 trio/trifecta が **0 件取得**。

見送り取りこぼし（passMiss）の大半も 3連単・3連複（下限合成 × scoreMin）。

### 2.3 データ品質メモ

- `synthesizeFactors`（`fetch-jra-snapshot.mjs`）が馬番・オッズから factors を仮生成
- 結果払戻に `trio` / `trifecta` が両日とも無い
- 評価上の `track` が両日すべて芝 → **解消済**（`ダ` 略記パース漏れ。7/26 はダート15／芝21）
- 会場別の仮想回収に極端な差（例: 7/25 中京 ≈2% vs 新潟 ≈166%）— 払戻キー突合の疑い

## 4. 各プランの詳細

### P0-1 券種的中ラベルを別建てする

- **なぜ:** 現行 hit は関係馬の最良着順≤3。3連系は1頭でも複勝圏なら hit になり適合率が水増しされる。
- **打ち手:** `evaluate` に `ticketHit`（払戻突合）と `placeCircleHit` を併記。週次の主指標を ticket Precision / 仮想回収率に寄せる。

### P0-2 3連複・3連単の払戻スクレイプを直す

- **なぜ:** 両日とも trio/trifecta 払戻 0 件。3連系の製品評価が不能。
- **打ち手:** `parseResultHtml` の払戻テーブル対応を拡張し、回帰用 HTML フィクスチャを追加。

### P0-3 候補密度を落とす

- **なぜ:** 密度≈166/レース。100倍台が候補の約8割。
- **打ち手:** まず `oddsThreshold` を 30〜50 に上げる／組み合わせは上位 N 件／ボードは馬グループ上位のみ。**1変更ずつ**感度実験。

### P1-1 合成 factors をやめ D4 接続

- **なぜ:** 高スコアほど placeHit 悪化。合成のままでは重み調整が無意味。
- **打ち手:** 人気順位導出 → `formSignal` を前走で置換 → `valueGap` 再定義。合成乱数成分を削除。

### P1-2 注目穴境界の再キャリブレーション

- **なぜ:** 注目穴 placeHit が抑えより低い（7/25: 34.6% vs 49.2%）。
- **打ち手:** 境界をデータ駆動で見直し、または「高スコア ∩ 中オッズ帯」など複合条件に。

### P1-3 券種別デフォルトと別 scoreMin

- **なぜ:** 単複の placeHit が極端に低い。全券種同一ゲートがノイズ源。
- **打ち手:** 初期は馬連・馬単・枠連を主表示。単複は別。3連系は scoreMin 引き上げまたは下限合成の厳格化。

### P1-4 related 合成の感度実験

- **なぜ:** passMiss の大半が 3連系（下限合成で落ちる）。
- **打ち手:** 同じ凍結オッズで合成方式だけ変えて再 freeze → evaluate。

### P2-1 オッズ複数時刻スナップ（D5）

- **なぜ:** 1日1凍結では締切直前ゲートの再現性が不明。
- **打ち手:** 朝・昼・締切前の3点保存。時刻別レポート。

### P2-2 ダート／距離パース監査

- **状態:** 対応済。netkeiba の `ダ1000m` 略記を認識。track 依存の枠バイアスも一本化。
- **なぜ:** 両日 track=芝のみは疑わしい（または実スケジュール要確認）。
- **打ち手:** RaceData01 を `芝|ダート|ダ|障` でパース。ライブ HTML と突合済み。

### P2-3 組み合わせ券取得の動的化

- **なぜ:** 現状 odds≥8 かつ券種ごと上位40件。閾値変更時にゲート集合を欠く恐れ。
- **打ち手:** 取得下限を `max(8, oddsThreshold-ε)` に。表示は別途 top-K。

### P2-4 厳選ボード UX

- **なぜ:** グループ化後も枠数が多すぎる。
- **打ち手:** 期待度 S/A のみ／スコア上位 M 枠／プリセット「厳選」。

### P2-5 検証ダッシュボード

- **なぜ:** JSON/CLI のみでレビュー摩擦が大きい。
- **打ち手:** `/method` または `/loop` に券種別・スコア帯チャート。

### P3-1 Want 因子（脚質・上がり・コース）

- **なぜ:** `paceFit` / `courseFit` が合成のままでは重み調整不能。
- **打ち手:** 成績ページ拡張後、因子を1つずつ置換。

### P3-2 会場別払戻突合ギャップ

- **なぜ:** 会場で仮想回収が極端に分かれる。
- **打ち手:** selection 表記ゆれをログし、突合失敗率を会場別に出す。

### P3-3 日記と自動レーンの比較

- **なぜ:** 日記は別レーン（Scorer に混ぜない）。比較だけ欲しい。
- **打ち手:** 同日のシステム候補 vs journal 回収率を並記。

### P3-4 Scorer 差し替え

- **なぜ:** ルール天井後の最終段。
- **打ち手:** インターフェース維持のまま別モジュール追加。合成解消＋数週の安定メトリクスが前提。
