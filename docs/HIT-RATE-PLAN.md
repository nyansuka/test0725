## 0. 「的中率」の定義（先に揃える）

| 指標 | 現状（20/60） | 製品上の意味 |
|------|---------------|--------------|
| **ticketPrecision**（券種払戻ヒット） | **≈0.44%** | **主指標。** 実際の馬券的中 |
| place Precision（関係馬≤3着） | ≈43〜45% | 参考のみ。3連系で水増しされやすい |
| 仮想回収率 | ≈70%（日差大） | 副指標。trio/trifecta 払戻欠損で偏りあり |
| 候補密度 | ≈166/レース | 制約。数件〜十数件を目標 |

複勝圏 Precision を上げても、ユーザーが買う馬券の的中には直結しない。  
**以降の「的中率」= ticketPrecision**（必要なら券種別・オッズ帯別も併記）。

## 1. 現状診断（ここまでの結果）

### 1.1 数字の要点

| 問題 | 証拠 |
|------|------|
| 実馬券的中が極低 | ticket 52/11949 ≈ 0.44% |
| 候補が閲覧不能 | 密度 ≈166。オッズ100+が約8割 |
| スコアが逆指標 | 注目穴 placeHit ≈32% ＜ 抑え ≈46%。高スコアほど悪化 |
| 単複が壊滅 | win ≈7%、place ≈4%（placeHit 定義でも） |
| 3連系の「高 Precision」は嘘 | trifecta placeHit ≈74% だが 1頭でも複勝圏なら hit |
| 合成 factors | 馬番・オッズから仮生成。重み調整は無意味 |

### 1.2 閾値スイープが示したこと

凍結オッズ固定・`scoreMin`/`oddsThreshold` のみ変更:

| 設定 | 密度 | ticketPrecision | 仮想RR | メモ |
|------|------|-----------------|--------|------|
| **20 / 60（旧基準）** | 166 | 0.44% | 70.5% | ノイズ過多 |
| **25 / 75（推奨帯）** | **7.4** | **0.93%** | 33.7% | 密度・ticket のバランス帯 |
| **20 / 80（現行デフォルトに近い）** | 0.7 | **4.0%** | 103% | 件数極少。日差・分散大 |
| 20 / 70 | 30 | 0.64% | — | まだ多い |

→ **ゲートを絞ると ticketPrecision は上がる**が、回収率・Recall はトレードオフ。  
→ 現行 `scoreMin=80` は「厳選」方向。件数不足なら **25/75** へ戻す候補。

### 1.3 根本原因の優先順位

```
① 測り方が歪む（placeHit / 3連払戻欠損）
② 候補集合が広すぎる（閾値・券種）
③ スコアが実力ではなく合成（D4 未接続）
④ その上でのラベル境界・重み調整
```

③を飛ばして WEIGHTS や「注目穴=70」をいじっても改善しない（既知）。

## 2. 目標（当面）

| 期間 | ticketPrecision | 密度 | 前提 |
|------|-----------------|------|------|
| **今〜2週** | **≥1%**（基準0.44%の約2倍） | 5〜15/レース | 閾値・券種フィルタのみ |
| **1ヶ月** | **≥2%**（券種別で馬連・ワイドを先に） | 同上 | D4（前走・人気）接続後 |
| **天井判断** | ルールで停滞したら Scorer 差し替え検討 | — | 合成解消＋数週の安定メトリクス後 |

副目標: 仮想回収率を「全券種合算」ではなく **払戻取得できている券種のみ** で出す。

## 3. 実行ロードマップ（1変更ずつ）

### Phase A — 正しく測る（的中率の土台）

| 順 | ID | 変更（1つ） | 完了条件 | 的中率への効き |
|----|-----|-------------|----------|----------------|
| A1 | P0-2 | 3連複・3連単の払戻パース修正 | evaluations に trio/trifecta の `payoutYen` が出る | 真の ticket 計測が可能になる |
| A2 | P0-1 | 週次レポートの主指標を ticketPrecision に | `loop:report` / trends に併記・主表示 | 「上がったつもり」を防ぐ |

**まだ触らない:** WEIGHTS、LABEL_SCORE_THRESHOLD。

### Phase B — 候補集合を絞る（即効・既にスイープ済）

| 順 | ID | 変更（1つ） | 仮説 | 見る指標 |
|----|-----|-------------|------|----------|
| B1 | P0-3 | デフォルトを **odds=25 / scoreMin=75** に寄せる（または現行80を維持して密度監視） | 密度↓で ticket↑ | ticket・密度・日次分散 |
| B2 | P1-3 | 初期 ON を **馬連・馬単・枠連・ワイド** に。単複・3連は OFF または別 scoreMin | 単複・3連のノイズを切る | 券種別 ticketPrecision |
| B3 | （任意） | オッズ上限キャップ（例: 表示候補は odds &lt; 80） | 100+ が支配しているノイズ削減 | オッズ帯別 ticket |

B1 はスイープで裏付けあり。B2 は別週。同時変更禁止。

### Phase C — スコアの嘘を消す（本命の精度向上）

| 順 | ID | 変更（1つ） | 完了条件 |
|----|-----|-------------|----------|
| C1 | P1-1 / D4 | 人気順位をオッズから導出 → `valueGap` を再定義 | 合成乱数成分を削除 |
| C2 | D4 | `formSignal` を前走着順・人気で置換 | 高スコア帯の place/ticket が逆転しないこと |
| C3 | P1-2 | 注目穴境界の再キャリブレーション | C1–C2 後のデータで決定 |
| C4 | P1-4 | related 合成（下限 vs 平均 vs k-of-n）感度 | 同じ凍結オッズで再 evaluate |

**ここが的中率の本丸。** 合成のまま閾値だけ上げても、残り候補の質は上がらない。

### Phase D — データ拡張（Cが効いた後）

| 順 | ID | 内容 |
|----|-----|------|
| D1 | P3-1 | 上がり3F・脚質・コース別成績を1因子ずつ |
| D2 | P2-1 / D5 | オッズ複数時刻スナップ（締切前ゲート） |
| D3 | P3-4 | ルール天井後の Scorer 差し替え |

## 5. 意思決定メモ

| 論点 | 仮決定 |
|------|--------|
| 追う的中率 | ticketPrecision（券種払戻）。place は補助 |
| 密度目標 | 5〜15 件/レース（厳選ボード前提なら 3〜8 も可） |
| 閾値の当面案 | 運用検証は **25/75**。件数不足なら 20/75。過多なら 25/80 |
| 券種 | 的中率改善フェーズでは 3連・単複を後回し |
| 合成 factors | 解消までラベル・WEIGHTS は触らない |
| 成功の見方 | 「候補を減らしながら ticket が上がる」こと。Recall 低下は許容（製品は全網羅ではない） |
